    Technical details

    Your password is stretched with scrypt (N = 217, r = 8, p = 1, which needs 128 MB of memory per guess), then the 32-byte private key is encrypted with AES-256-GCM. Every backup is decrypted once as a self-check before you can save it, and every restored key is checked against its address. Backups are fully validated when loaded, and only settings from N = 214 to 218 with r = 8, p = 1 are accepted, so a crafted backup can't freeze the page.

    The page's security policy allows only its own script, identified by its SHA-256 hash, and blocks network requests. Peer-to-peer connections are disabled at startup.

    Backup file, version 1

    {
  "type": "brc-vault-backup",
  "version": 1,
  "address": "<64 hex: the wallet's public key>",
  "kdf": { "name": "scrypt", "logN": 17, "r": 8, "p": 1, "dkLen": 32,
           "salt": "<32 hex: 16 random bytes>" },
  "cipher": { "name": "aes-256-gcm", "iv": "<24 hex: 12 random bytes>" },
  "ciphertext": "<96 hex: encrypted key + 16-byte tag>",
  "created": "YYYY-MM-DD",
  "note": "…"
}

    Key = scrypt(password normalized to NFKC, salt, N = 2^logN, r, p, 32). Ciphertext = AES-256-GCM(key, iv, private key) with associated data brc-vault-backup|1|address|scrypt|logN|r|p|dkLen|salt|iv, so changing any field makes decryption fail.

    The paper code is the same backup on one line, in upper case: BRCVAULT1:ADDRESS:LOGN:R:P:SALT:IV:CIPHERTEXT, and that is exactly what the QR code holds. Phone camera apps deliberately can't do anything with it: they don't recognise the BRCVAULT1: prefix, so they never offer to search the web for it. Scan it with BRC Vault's own scanner instead, which reads the camera inside the page and sends nothing anywhere. On paper it's printed one part per line, each followed by a check in brackets: the first 4 hex characters of SHA-256 of that line with spaces removed. A typo is caught and the line named before the slow password step. An unprotected key is printed as BRCKEY1:KEY:CHECK, where CHECK is the first 8 characters of the address, so it can't be mistaken for an address and a typo in the key is caught.

    Recovery words

    The 24 recovery words are standard BIP39 English, with the 32-byte private key used directly as the entropy (no passphrase, no derivation path). That is exactly what the BRC Wallet Android app shows and accepts, so the same words work in both. When you type them here, commas and capital letters don't matter and the first four letters of each word are enough; if you number the words, the numbers set the order. The Android app needs the full words in lower case, in order.

    Other wallets' files

    Password-protected files from the BRC Wallet desktop app ("type": "browsercoin-wallet", "version": 2, "encrypted": true) open in Restore. They use scrypt with the password exactly as typed and AES-256-GCM with a separate authTag; the same setting limits apply.
